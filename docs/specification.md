# Реализация требований ТЗ

Источник: [Adrobot ТЗ](https://app.notion.com/p/mnovikov/Adrobot-2b01eb78a7bb80a1b188c3a4a1cad55e), повторно прочитан 21 ноября 2026 года. Для редактора ТЗ ссылается на [видео](https://youtu.be/jNloscEWCjA). Внешний вид разрешено выбирать самостоятельно.

## Создатель

Пользователь вводит название и числовой ID существующего оффера Keitaro, затем выбирает страну по названию и двухбуквенному коду. Сервер проверяет код по ISO 3166-1 alpha-2. Название оффера подсказывается из каталога. Домен, группа кампаний и источник выбираются из API. До начала создания сервер проверяет наличие выбранных ID.

Новая кампания использует ротацию по позиции, выбранные домен, группу и источник. Сначала она создаётся отключённой, затем настраиваются:

1. Активный обычный поток на позиции 1. Единственный фильтр — принятие выбранной страны. Действие — HTTP-перенаправление на `https://www.google.com/`. Офферов и лендингов нет.
2. Активный поток по умолчанию на позиции 2. Фильтров и лендингов нет. Единственный выбранный оффер активен и получает 100% трафика этого потока.

Триггеры, способные менять маршрутизацию, не создаются. Перед включением сервер перечитывает кампанию и потоки и проверяет весь этот набор требований. После включения выполняется повторная сверка. При обнаружении несоответствия в активной созданной кампании приложение отправляет отключение и проверяет его результат. Если отключение не подтверждено, интерфейс сообщает об этом явно.

Реализация: `adrobot/domain/stream_rules.py`, `adrobot/domain/creation_rules.py`, `adrobot/services/creation.py`. Приёмочные проверки: `tests/test_creation_spec.py`, включая 16 вариантов неверной конфигурации. Это проверки данных API, а не имитация реального геотаргетинга Keitaro.

## Редактор

| Требование | Реализация и проверка |
|---|---|
| Выбрать существующую кампанию и загрузить её потоки | Приложение читает все страницы списка кампаний с `offset=0` и загружает потоки выбранной кампании |
| Для потоков без офферов не показывать редактор долей | Прямой редирект показывается заголовком. В пустом потоке `landings` форма открывается по кнопке «Добавить первый оффер». Восстановление доступно через архив |
| Добавить оффер | Поиск по названию/ID, локальный черновик, перераспределение долей |
| Удалить оффер | Удаление из активного набора, оставшиеся доли перерасчитываются |
| Закрепить долю | Закреплённая доля сохраняется при добавлении/удалении остальных |
| Правильные целые проценты | Сумма активных долей 100%. Три оффера получают 33/33/34. При закреплённых 25% два других получают 37/38. Для нового или восстановленного оффера требуется положительная доля |
| Явно опубликовать или отменить | Изменения не отправляются до публикации; отмена удаляет локальный черновик |
| Архив и восстановление | Удалённые офферы показываются серыми с 0%; опубликованная история хранится в SQLite |
| Внешние удаления | При повторной загрузке известные исчезнувшие офферы попадают в локальный архив |

Проверки: `frontend/tests/shares.test.mjs`, `tests/test_campaigns.py`, `tests/test_creation_spec.py`, `tests/test_http.py`. Публикация использует проверку версии и восстановление после потерянного ответа.

## Стек и сдача

Backend использует FastAPI, SQLAlchemy и Alembic. Frontend использует React, TypeScript и Vite. Команды миграции и запуска описаны в README. [Репозиторий для сдачи](https://github.com/QWERN-9876r/Adrobot).

## Граница подтверждённого результата

21 ноября 2026 года на тестовом Keitaro подтверждены создание и включение отдельной кампании, её домен, группа и источник, а также оба маршрута через Click API. Запрос с австралийским IP выбрал поток с HTTP-редиректом на Google, запрос с IP вне Австралии выбрал поток с оффером. Через редактор проверены удаление связи с оффером, архив и восстановление с долей 100%. Тестовая кампания отключена и перемещена в архив. [Keitaro Click API](https://docs.keitaro.io/en/development/click-api.html).

Текущему ключу на стенде доступен один активный оффер. Сценарий с несколькими офферами проверен в локальном браузерном демо на чистой базе. После отмены черновик исчезал, после публикации удалённые строки оставались в архиве, а восстановление при закреплённых 25% дало доли 25%, 37% и 38%. Автоматические тесты проверяют эти правила с локальной SQLite и подменённым трекером.
