# Управление кампаниями Adrobot

Локальное приложение для создания кампаний Keitaro и редактирования офферов в потоках. Интерфейс написан на React и TypeScript и собирается Vite. FastAPI отдаёт собранный интерфейс и API, а SQLAlchemy работает с SQLite.

Поддерживаются macOS и Linux, локальная SQLite на одном компьютере. Межпроцессные блокировки используют `flock`; не размещайте базу на сетевом диске. Нужны Python 3.9 или новее и Node.js 22.12 или новее. Node.js нужен для разработки и сборки интерфейса.

## Запуск демо

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
alembic upgrade head
npm --prefix frontend ci
npm --prefix frontend run build
python app.py
```

Откройте [Adrobot на локальном сервере](http://127.0.0.1:8000). В демо уже есть кампания для Австралии с тремя офферами и каталог для создания новых кампаний. Данные демо и история опубликованных изменений хранятся в SQLite.

## Миграции базы данных

Команда `alembic upgrade head` создаёт таблицы в новой базе или регистрирует таблицы предыдущей версии без изменения записей. По умолчанию используется `adrobot.sqlite3` в корне проекта. Если база находится в другом месте, задайте один и тот же `ADROBOT_DB` для Alembic и приложения.

Перед обновлением существующей базы остановите приложение и сохраните резервную копию файла SQLite. Для отката к предыдущей версии восстановите копию и запустите предыдущую версию приложения.

## Разработка интерфейса

Установите зависимости и примените миграции как при запуске демо. В одном терминале запустите API, в другом — Vite.

```sh
ADROBOT_DEV=1 python app.py
```

```sh
npm --prefix frontend run dev
```

Откройте [сервер разработки Vite](http://127.0.0.1:5173). Vite обновляет интерфейс при изменениях и передаёт запросы `/api/` на Python-сервер. Если API запущен на другом порту, передайте то же значение `PORT` при запуске Vite. Команда `npm --prefix frontend run typecheck` проверяет типы. Сборка также выполняет эту проверку.

## Подключение к Keitaro

Заполните `.env` в корне проекта (если файла нет, скопируйте `.env.example`). Он автоматически загружается приложением и Alembic независимо от текущей папки терминала:

```dotenv
KEITARO_URL=https://адрес-твоего-keitaro
KEITARO_API_KEY=твой-api-ключ
PORT=8000
```

`KEITARO_URL` — базовый HTTPS-адрес без `/admin_api/v1`. Для запросов к Admin API укажите ключ в `KEITARO_API_KEY`. [Авторизация Keitaro](https://docs.keitaro.io/en/development/admin-api.html).

Переменные окружения терминала имеют приоритет над `.env`. Значения с пробелами или `#` заключайте в кавычки. Подстановка `${...}` отключена, чтобы значения загружались буквально. После изменения `.env` перезапустите сервер. Для публикации используется шаблон `.env.example`, а рабочий `.env` исключён из Git.

Установите зависимости командой `python -m pip install -r requirements.txt`, затем запускайте приложение как обычно. Ключу нужны права на чтение кампаний, потоков, офферов, доменов, групп кампаний и источников трафика, а также права на запись кампаний и потоков. Запускайте приложение на локальном сервере. Порт можно изменить через `PORT`, путь к файлу SQLite — через `ADROBOT_DB`.

Перед включением кампании приложение проверяет оба сохранённых потока. На тестовом трекере проверьте фильтр по стране и оба маршрута перенаправления. Демо работает с тестовыми данными, а совместимость с реальным трекером зависит от его версии и формата передачи URL при создании потока.

## Создание кампании по ТЗ

Введите название и **ID оффера Keitaro**, затем выберите страну по названию и коду ISO 3166-1 alpha-2, домен, группу и источник. Программа создаёт два потока. Трафик из выбранной страны уходит на Google, остальной — на выбранный оффер с долей 100%. Настройки кампании и обоих потоков проверяются до и после включения.

Демонстрационная кампания с тремя офферами предназначена для проверки редактора. Она не является результатом нового создания: новые кампании получают один выбранный оффер.

[Соответствие пунктам ТЗ и приёмочные проверки](docs/specification.md).

## Редактирование кампании

1. Выберите кампанию. Её потоки загрузятся автоматически. Для потоков с прямым перенаправлением отображается только название.
2. Найдите оффер по названию или ID. Для пустого потока откройте выбор кнопкой «Добавить первый оффер». Удалённый оффер можно восстановить из архива.
3. Закрепите долю оффера, чтобы она сохранялась при изменении списка. Оставшаяся доля распределяется максимально равномерно в целых процентах. При закреплённых 25% два остальных оффера получат 37% и 38%. Если закрепления не оставляют новому офферу хотя бы 1%, редактор попросит освободить долю.
4. Опубликуйте черновик или отмените изменения. После публикации удалённые офферы можно восстановить из архива. Чтобы увидеть изменения, сделанные напрямую в Keitaro, загрузите потоки заново.

[Документация Keitaro Admin API](https://admin-api.docs.keitaro.io/)


## Обновление после ревью

Остановите прежний сервер, сохраните резервную копию SQLite, затем выполните:

```sh
alembic upgrade head
npm --prefix frontend ci
npm --prefix frontend run build
python app.py
```

Миграция `0002_operations` добавляет журнал создания кампаний и проверяет формат прежней истории потоков. Приложение откажется запускаться, если ревизия базы не совпадает с актуальной. Данные прежнего демо и история сохраняются.

## Публикация, конфликты и восстановление

Версия потока учитывает офферы, состояние потока и локальную версию закреплений. Устаревший черновик получает конфликт вместо перезаписи закреплений. После внешнего отключения оффера его закрепление снимается при загрузке.

Перед удалённой записью намерение публикации сохраняется в SQLite. Если ответ потерян, приложение читает поток повторно. Если офферы совпадают с ожидаемыми, оно завершает сохранение закреплений и архива. Если чтение недоступно или результат другой, повторный PUT автоматически не отправляется. Загрузите потоки заново. При несовпадении после ручной проверки в Keitaro можно нажать «Принять состояние Keitaro»: местный черновик будет отменён, неопределённая операция закрыта. Сначала убедитесь, что предыдущая запись на стороне Keitaro завершилась.

**Ограничение внешней конкуренции:** в проверенной [документации Admin API](https://admin-api.docs.keitaro.io/) не найден подтверждённый механизм атомарной условной записи. Повторная проверка перед PUT сокращает окно гонки, но не исключает изменение через Keitaro между последним GET и PUT. До подтверждения поддержки такого механизма конкретной версией трекера не редактируйте один поток одновременно через Adrobot и напрямую в Keitaro. Между процессами Adrobot с общей локальной базой запись защищена блокировкой конкретного ресурса.

Общий сетевой mutex удалён: чтение справочников и работа с другими ресурсами не ждут медленную публикацию одного потока. При занятом ресурсе API возвращает `409` с кодом `busy`.

## Повтор создания кампании

Форма сохраняет идентификатор и параметры попытки в хранилище вкладки до отправки запроса. Сервер сохраняет журнал операции и стабильный alias до POST. После сетевой ошибки используйте «Проверить и продолжить» в той же вкладке. Если нужно создать другую кампанию, нажмите «Начать новую кампанию». Кнопка освобождает форму, а предыдущую кампанию можно проверить в Keitaro.

Приложение ищет уже созданную кампанию и потоки и продолжает настройку. Если ранее отправленный POST не подтверждён и соответствующая сущность не найдена, новый POST блокируется: отсутствие ответа не доказывает отсутствие записи. В таком случае проверьте alias из сообщения и состояние кампании в Keitaro. Автоматической очистки/удаления частично созданных кампаний нет; они остаются доступными для проверки. Полностью безопасно автоматически повторить такой POST без поддержки идемпотентности сервером нельзя.

Черновики офферов остаются в памяти страницы. При уходе с неопубликованными изменениями браузер показывает предупреждение; восстановление черновиков после принудительного закрытия браузера не реализовано. «Обновить кампании и потоки» перечитывает также список кампаний, включая внешние создания и удаления.

## Проверки

Сверка с предоставленным `openapi.yaml` описана в [отчёте по API](docs/openapi-review.md). Для тестов установите дополнительные зависимости:

```sh
python -m pip install -r requirements-dev.txt
npm --prefix frontend test
npm --prefix frontend run build
python -m unittest discover -s tests -v
```

Python-тесты проверяют бизнес-правила, реальные ASGI-маршруты FastAPI, миграции и сбои интеграции через независимый подменённый трекер. Frontend-тесты проверяют доли, неизменяемость черновика, форматы ответов и сохранение идентификатора создания. Они не обращаются к реальному Keitaro и не изменяют рабочую базу. GitHub Actions запускает проверки после публикации репозитория.

## Структура проекта

Backend организован в пакете `adrobot`: `api` — HTTP-контракты и маршруты, `domain` — правила и интерфейс трекера, `services` — бизнес-операции, `infrastructure` — БД, блокировки и адаптеры. Корневой `app.py` отвечает только за запуск.

Frontend разделён на `app`, `api`, `features/campaigns`, `features/streams`, `features/workspace`, `shared` и `styles`. Иконки лежат в `frontend/public/brand` и доступны и в Vite, и через Python-сервер.

Подробное дерево и правила зависимостей: [архитектура](docs/architecture.md). Исходник и промпт иконки: [генерация иконки](docs/icon-generation.md).

Коды ошибок `conflict`, `busy`, `uncertain`, `upstream_contract` позволяют интерфейсу отличать конфликт и неизвестный результат от обычной ошибки. Перенос модулей не меняет схему базы или API; новая миграция для этого рефакторинга не нужна.


## Логи запросов к Keitaro

Подробное HTTP-логирование включено по умолчанию (`KEITARO_DEBUG_HTTP=1`). Логи выводятся в терминал (stderr) и связываются общим ID:

- `http_request`: метод, полный URL с query-параметрами, заголовки приложения, JSON-тело и таймаут;
- `http_response`: URL ответа, статус, reason, заголовки, полное тело и размер в байтах, включая HTTP-ошибки;
- `http_error` / `http_validation_error`: тип и описание сетевой ошибки либо ошибка проверки ответа;
- `request_started` / `request_finished`: начало, результат и длительность в миллисекундах.

Тела записываются целиком. JSON записывается как структура, остальные ответы — текстом UTF-8. Приложение логирует доступные ему заголовки. API-ключ, поля с именами password/token/secret/authorization/cookie/api-key и учётные данные в URL HTTP-прокси маскируются. Произвольные персональные данные и секреты в свободном тексте могут оставаться в диагностике, поэтому файл логов исключён из Git.

```sh
python app.py 2>> adrobot.log
```

Для краткого режима задайте `KEITARO_DEBUG_HTTP=0` и перезапустите сервер. В нём сохраняются только начало, завершение, метод, путь без query, статус, длительность и класс ошибки.
